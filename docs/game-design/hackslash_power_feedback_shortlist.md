# 厳選版:射幸性 × ゲーム成立性で絞った15案

前提:4人マルチ / ハクスラ / カジュアルアクション / ドロップ非即時反映
母集団:`hackslash_power_feedback_ideas.md` の全93案

---

## 0. 選別基準

### 2軸スコアリング

| 軸 | 定義 | 5点の条件 |
|---|---|---|
| **射幸性** | 「もう1回」を生む強度 | 不確実性の解消が多段化し、かつ他人に伝染する |
| **成立性** | カジュアル4人アクションとして壊れないか | テンポを損なわず、下手な人を罰せず、実装が現実的 |

**採用条件**:射幸性4以上 かつ 成立性4以上。片方が5でも他方が3以下なら不採用。

### カジュアル4人マルチ固有の3つの禁則

| 禁則 | 理由 | 設計上の帰結 |
|---|---|---|
| **降格フェイクを作らない** | 「騙された」はカジュアル層の離脱要因。パチンコ客は文法を学習済みだが本作の客は違う | 昇格演出は**必ず上方向のみ**。低く見せて上げるのは可、高く見せて下げるのは不可 |
| **拾った瞬間に情報ゼロにしない** | 非即時反映で「何も分からない」はアクションの手応えを直接削る | 取得時に**先読み色は必ず出す**。隠すのは中身であって期待値ではない |
| **上手い人しか得しない設計にしない** | 4人中2人が置いていかれると解散する | 倍率・ボーナスは**減点型でなく加点型**。被弾でリセットしない |

### テンポ予算

| 区間 | 上限 | 根拠 |
|---|---|---|
| インゲームの1ドロップ演出 | 0.4秒(高レアのみ1.0秒) | アクションの手を止めない |
| リザルト全体(4人分) | 25秒 | これを超えると2周目以降スキップされる |
| 高レア開示のスキップ不可区間 | 0.8秒 | 「見せる」と「待たせる」の境界 |

## 1. インゲーム(拾ったとき)— 採用5件

### IG-1. 保留ストリップ(基盤)
> 母集団: 1-14 / 1-18 / 1-2

| 項目 | 内容 |
|---|---|
| 仕掛け | 拾ったアイテムはHUD下部の「保留ストリップ」に色付きアイコンで積まれる。中身(名前・数値)は不明、**色=先読み度だけは即座に見える**。一定確率で色を持たない「?」保留が出現し、この枠の期待値を最も高く設計する |
| 射幸性 | 4 |
| 成立性 | 5 |
| なぜ効くか | 非即時反映という制約を「保留=未確定の期待の在庫」に読み替える。ランの進行がそのまま期待の積み増しになる |
| 成立の担保 | 色を出すので手応えは失われない。「?」は全体の10〜15%に抑え、常時謎だらけにしない |
| 実装コスト | 小(HUD + データ構造) |
| 検証指標 | ラン完走率、保留数と継続プレイの相関 |

**設計注記**:これは単独の演出ではなく他14案の土台。先に実装しないと他が乗らない。

### IG-2. パーティ共有ドロップ倍率 → ラッシュ突入
> 母集団: 1-23 / 1-10 / 1-22

| 項目 | 内容 |
|---|---|
| 仕掛け | 画面上部に「DROP ×1.0」。**4人の撃破が合算**されて上昇し、時間経過でゆっくり減衰する。×3.0到達で画面が染まり「RUSH」突入、一定時間ドロップ率と光柱の派手さが跳ね上がる |
| 射幸性 | 5 |
| 成立性 | 5 |
| なぜ効くか | スロットの上乗せ数字と確変突入を、アクションの操作そのものに接続する。数字が回っているだけで手が止まらない |
| 成立の担保 | **被弾でリセットしない**(減衰のみ)。合算方式なので上手い1人が牽引でき、下手な人も同じラッシュに乗れる。共有なので煽りでなく協力の空気になる |
| 実装コスト | 中(全員の撃破同期 + ドロップテーブル切替) |
| 検証指標 | ラッシュ到達率、ラッシュ中の1分あたり撃破数、セッション長 |

**設計注記**:本案が本企画で最も「ゲームとして機能する射幸装置」。数字の上昇が戦闘の目的になる。

### IG-3. 保留昇格(行動連動)
> 母集団: 1-15 / 1-16

| 項目 | 内容 |
|---|---|
| 仕掛け | ラン中の達成(ボス撃破、ノーダメージ区間、ラッシュ到達)のたびに、保留ストリップの1〜2個が**その場で色を上げる**。専用SEとスパーク。降格は絶対に起こさない |
| 射幸性 | 5 |
| 成立性 | 4 |
| なぜ効くか | パチンコの保留変化そのもの。「さっき拾った微妙なアイツが金になった」は単発ドロップより記憶に残る |
| 成立の担保 | 抽選は取得時に確定済みで、昇格は**開示の段階化**として実装する。すなわち内部では最終レア度を先に決め、初期表示を意図的に低く見せる。上げ幅は最大2段まで |
| 実装コスト | 中(演出パステーブルの設計が本体) |
| 検証指標 | 昇格発生時のプレイ継続率、演出→結果の対応率ログ |

**設計注記**:「初期表示を低く出す」ことの正当性は、降格が存在しないため「表示は最低保証値」と解釈できる点にある。ここは規約表記も含めて整合させる。

## 2. リザルト — 採用5件

### RS-1. 保留消化変動 + 段階昇格 + 文字予告

| 項目 | 内容 |
|---|---|
| 仕掛け | 保留を1個ずつ変動させて開示。低レアは0.4秒で流し、色付きは自動で減速する。ホイールが止まった後に**もう1段上がる**昇格を最大2回。背景に「熱」「激」「確」の漢字1文字が叩きつけられる |

| 成立性 | 4 |

| 成立の担保 | 全体を通常10秒以内。**スキップ可**にし、高レア開示の0.8秒のみスキップ不可。漢字予告は多用せず全体の2割以下 |

### OG-4. 確変モード + 連チャンバッジ

## 4. 15案の連結 — 1本の導線

```
[インゲーム]

                                         ↓
                              IG-3 ラン中に保留が昇格する
                                         │
[リザルト]                               ↓
 RS-1 変動して段階昇格 → RS-2 ボタンで確定 → RS-3 4人同時に祭り
                                         ↓
                              RS-5 終わりかけで復活
                                         ↓
                              RS-4 仮想戦闘力がカウントアップ
                                         │
[アウトゲーム]                           ↓
 OG-1 一括装備で現金化 → 次の壁が見える
                                         ↓
 OG-2 鑑定で第2抽選 → OG-3 強化でもう1回 → OG-5 ロビーで見せる
                                         ↓
                              OG-4 確変が残り3ラン → 次のランへ
```

**1アイテムあたりの「当たるかも」回数**:取得時の色(1) → 保留昇格(2) → リザルト変動昇格(3) → 復活枠(4) → 鑑定サブステ(5) → 強化大成功(6)。**同じドロップ量で6倍の抽選体験**を作れる。

## 検証ブロック

**妥当性**:選別の2軸は、射幸性側がパチンコ・スロットの実証済み文法に、成立性側がカジュアル協力ゲームの離脱要因に対応しており、根拠の性質が異なる2つの制約で挟み込めている `[ESTIMATE]`。個別案の効果量は未計測 `[HYPOTHESIS]`。

**制約**:演出が抽選結果を変えない原則は全案で維持しているが、IG-3の「初期表示を低く見せる」は表示倫理の境界にあり、降格を作らない(表示は最低保証)という一貫性で担保している。有償通貨がドロップ率や強化に絡む場合は確率表示等の法令対応が別途必須。戦闘力の単一指標化はビルド多様性とトレードオフになる。

**改善余地**:信頼度テーブルの具体数値、ラッシュの発生頻度と持続時間、鑑定サブステの上振れ幅の上限、確変3ランという数値の妥当性。いずれも実測なしには決まらない。

**次アクション**:P0の4案でプロトタイプを組み、リザルト滞在時間・一括装備使用率・1セッションあたりラン数を基準値として取得する。その後P1をA/Bで積み増し、各案の増分効果を単独で測る。
