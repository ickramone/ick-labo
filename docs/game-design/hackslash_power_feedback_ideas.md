# ハクスラ「どんどん強くなる感」ブースト案
## 前提:4人マルチ / カジュアルアクション / ドロップ非即時反映

---

## 0. 構造の再定義 — 非即時反映は制約ではなく「保留」構造

パチンコの快楽構造は「入賞 → 保留(未確定の期待を貯める)→ 変動・リーチ(段階的開示)→ 大当たり(確定)→ 出玉・連チャン(蓄積の可視化と継続)」である。
本作の3シーンはこれに一対一で写像できる。

| パチンコ | 本作 | シーンの役割 |
|---|---|---|
| 入賞・保留 | 拾う(インゲーム) | **期待の入金** |
| 変動・予告・リーチ・大当たり | リザルト | **段階的開示と確定** |
| 出玉・ドル箱・確変継続 | アウトゲーム | **蓄積の可視化・実装・次への導線** |

### 心理原理 → パチンコ実装 → 本作での使い所

| 原理 | パチンコ/スロット | 本作 |
|---|---|---|
| 変動比率強化 | 大当たり確率 | ドロップ抽選 |
| 段階的不確実性解消 | 先読み→予告→リーチ→当たり | 拾う→保留色→変動→開示→鑑定→強化 |
| ニアミス効果 | リーチはずれ | 「あと1マス」「推奨値まであと◯」 |
| 昇格 | 保留変化・昇格演出 | レア度が後から上がる |
| 復活 | はずれ後の逆転 | 終了後の追加1枠 |
| 統制の錯覚 | ボタン押し・連打 | 開封連打・ボタン確定 |
| ツァイガルニク効果 | 未消化保留 | 未鑑定・未装備バッジ |
| 蓄積の可視化 | ドル箱・出玉数 | 倉庫の箱・戦闘力カウントアップ |
| 社会的伝染 | 隣の台の大当たり音 | 4人共有演出・祝福・ロビー発光 |
| 状態の継続 | 確変・ST・ラッシュ | ドロップ率UPモードの継続と失効 |

**設計原則**:演出は抽選結果を変えない。抽選は取得時に確定し、演出は「開示の順序と速度」だけを制御する。信頼度(演出→結果の対応率)は表で管理し、嘘はつかないが情報を小出しにする。

## 4. 貫通設計 — 3シーンを1本の導線にする

1. **「保留」を唯一の一次オブジェクトにする**。インゲーム=貯める、リザルト=開示、アウトゲーム=実装。HUDアイコン・リザルトカード・倉庫アイコンは同一ビジュアル言語で描く。
2. **信頼度階層を6段階で統一**。色・音・間(タメ時間)・カットインの有無を全シーンで同一マッピングにし、プレイヤーが「文法」を学習できるようにする。
3. **1アイテムに最大5回の「当たるかも」を仕込む**:拾う(色示唆)→保留変化(昇格)→リザルト変動(昇格・復活)→鑑定(サブ確定)→強化(大成功)。
4. **個人の当たりを必ず他3人に伝播させる**。マルチは羨望と祝福で射幸を倍加する装置である。

## 検証ブロック

- **妥当性**:パチンコ文法(保留・先読み・昇格・復活・確変)は数十年の実戦で射幸性が検証済み。非即時反映を「保留」に読み替える写像は構造的に整合する。個々の案の効果量は未検証(`[HYPOTHESIS]`)。
- **制約**:演出は抽選結果を変えない原則を守ること。有償通貨が絡む場合は確率表示等の規制対応が必須。ニアミス・擬似連の過剰は不快と離脱を招くため頻度上限を設ける。4人の待ち時間(順番開示)はテンポ設計で相殺が必要。演出コスト(音・ムービー)は段階数に比例して増える。
- **改善余地**:信頼度表の具体値、スキップ可否の閾値、共鳴・祝福の実利バランス、カジュアル層に対する「パチ文法の学習コスト」の測定。
- **次アクション**:優先案1〜3をプロトタイプし、リザルト滞在時間・再走率・装備変更率をA/Bで計測する。
